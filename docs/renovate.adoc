[#renovate]
= Dependency updates (Renovate)

Dependency updates are handled by https://docs.renovatebot.com/[Renovate],
configured in `renovate.json` in the repository root.
Renovate opens pull requests, which are reviewed and merged manually as usual.

== What is updated

Renovate only looks at the `.env` file and tracks two versions:

[options="header",cols="1,1,2"]
|===
|Dependency |`.env` key |Source
|*docker-base* (`icellmobilsoft/base` images) |`BASE_IMAGE_VERSION` |Docker Hub
|*WildFly* (`org.wildfly:wildfly-galleon-pack`) |`WILDFLY_VERSION` |Maven Central
|===

Everything else (Dockerfiles, compose files, scripts) is not touched by Renovate.

== Which branches

* `main`
* every `release/docker-wildfly-X.Y.x` branch

Each branch is updated separately, so a release branch gets updates for its own WildFly / docker-base line.

== When and how

There are two ways a PR gets created:

* *automatic* - Renovate opens the PR on its own as soon as a new version is available.
* *approval* - the update only shows up as a checkbox on the *Dependency Dashboard* issue.
The PR is created once someone ticks the checkbox.

=== WildFly

[options="header",cols="1,2,2"]
|===
|Update |`main` |release branches
|patch |automatic |automatic
|minor |automatic |approval
|major |approval |never
|===

=== docker-base

[options="header",cols="1,2,2,2"]
|===
|Update |`main` |release branches *6.0.x and newer* |release branches *older than 6.0.x*
|patch |automatic |automatic |approval
|minor |automatic |approval |never
|major |approval |never |never
|===

On `main`, if a docker-base minor *and* patch version are both available,
only one PR is created for the newest (minor) version - no separate patch PR.

On release branches 6.0.x and newer patch and minor are handled separately: the patch PR is created automatically,
the minor one only after approval.

On release branches older than 6.0.x even docker-base patch updates are known to break the images,
so patches need approval and minor updates are not offered at all.

== Pull requests

Updates are grouped, so a branch has at most one open PR per kind:

[options="header",cols="1,3"]
|===
|PR |Contains
|patch updates |all automatic patch updates of the branch (WildFly, and docker-base on `main` / 6.0.x+)
|minor updates |WildFly minor update (automatic on `main`, approved on release branches)
|docker-base minor updates |docker-base minor update (automatic on `main`, approved on 6.0.x+)
|docker-base patch updates |docker-base patch update on branches older than 6.0.x (approved)
|major updates |approved major updates, `main` only
|===

All PRs get the `dependencies` label, plus `patch` / `minor` / `major` where applicable,
and use `chore(deps): ...` commit messages.

TIP: To request an update that needs approval, open the *Dependency Dashboard* issue in the GitHub repository
and tick the checkbox next to it.
